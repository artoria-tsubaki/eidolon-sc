# 对话中发送图片

用户确认：文字对话单图，可附文字；独立视觉模型；保留图片和按需重看；支持部署者及用户自带视觉配置；只有用户明确描述或确认的信息进入长期记忆。

## 行为

- 选择、粘贴、拖拽一张图片，可移除；图片和附言作为同一条消息，允许图片无附言。通话期间禁用。
- 上传、看图、流式回复状态清晰；失败保留草稿；失败回合不进入正式历史。
- 视觉模型结合当前附言和近期上下文输出可见内容、文字、相关观察与不确定性；观察独立于用户原文，不扮演偶像。
- 现有对话模型结合观察、人设和历史回复，保留日语、中文字幕和朗读行为。
- 历史含图片及摘要，支持 inspect_user_image(image_id, question)，每回合最多重看一张一次，与剧情检索预算独立；只能访问本用户本对话已提交图片。查看器有“问这张图”入口。
- 记忆提取要求用户文字依据，不能把图片观察或角色复述自动当成用户事实。

## 接口与生命周期

- 对话内鉴权上传/读取；回合增加互斥的 image_id / referenced_image_id，有新图片允许空文字，引用必须有问题；增加请求标识防止重复提交。
- SSE 增加看图阶段；历史消息增加用户图片元数据，独立于角色生成的 photo。
- SQLite 保存规范化图片及观察，先暂存，回合成功时原子绑定；24 小时清理未绑定上传。
- JPEG、PNG、静态 WebP；最大 10 MB、4000 万像素，长边 2560，修正方向和清理 EXIF。
- 删除用户/对话一并清理；数据包包含图片并重映射标识，兼容旧包；数据库备份包含图片。
- 图片不公开，读取校验所有权并 no-store；日志不含图片编码、观察正文或密钥。

## 模型配置与费用

- 独立图片理解配置（地址、协议、模型、密钥、超时、并发、限额），适配已有三个 LLM 协议。用内置图片验证能力。
- 用户密钥仅在浏览器保存、请求期间服务器持有；自带失败不回退；继承现有 SSRF 与代理约束。
- 部署者默认每用户每小时 20 次、并发 2、超时 60 秒，可后台调整。首次解析与重看各算一次；自带不占部署者额度。
- 看图实际调用及失败独立计量；角色回复失败不抹去已发生费用。

## Testing Decisions

协议适配通过请求内容验证；图片模块通过公开存取/解析接口验证；回合通过现有引擎与 HTTP 测试验证；前端通过状态/API 测试及类型检查验证。覆盖图文混合、纯图、上下文、旧图引用、失败重试、越权、并发重试、过期清理、删除、导入导出、密钥选择、限额、记忆来源和原功能回归。

用户约束：不执行构建/打包，不启动开发服务器，不使用浏览器或 computer use 访问业务系统。用户自行做页面验收。
